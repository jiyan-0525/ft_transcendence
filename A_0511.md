## 2. Decisions to lock on Day 1

Record these in the PR description; only reopen them if something breaks.

| Decision | Choice | Reason |
|---|---|---|
| Runtime | Node 22 (`nvm use 22`) | Matches CI and README |
| Build | Vite 5.4 + `@vitejs/plugin-vue` | Stable, works on Node 18/20/22 if someone falls back |
| Framework | Vue 3.5 + TypeScript (strict) | Agreed stack; strict mode catches contract drift |
| Router / state | Vue Router 4 + Pinia 2 | PLAN §2 |
| Styling | Tailwind CSS 3.4 + CSS variables | Classic config makes token demos predictable |
| Tests | Vitest 2 + `@vue/test-utils` 2 | Fast, same Vite pipeline |
| Lint | ESLint 9 flat config + `eslint-plugin-vue` + `typescript-eslint` | Matches current tooling |
| API base | `import.meta.env.VITE_API_URL`, default `/api` | Same-origin in dev via proxy |
| Dev transport | Vite proxy `/api` and `/ws` → `http://localhost:3000` | Avoids CORS and cross-site cookie problems |
| Auth transport | HTTP-only session cookie, `credentials: "include"` | protocol §2.2 |
| Backend offline mode | `VITE_USE_MOCKS=true` + in-memory mock handlers | Unblocks A while B builds auth |
| Path alias | `@` → `src` | Keeps imports stable |
| Naming | Components `App*`, views `*View.vue`, stores `use*Store` | Consistent with scaffold conventions |

**Fallback:** if Node 22 is unavailable on a machine, use Node 18 with Vite 5.4.
Do not mix Node versions between local and CI.

## 6. Contract A needs from B (send this list to B today)

A codes against these; any change goes into `docs/protocol.md` first.

### 6.1 Auth endpoints

```http
POST /api/auth/register
{ "email": "a@example.com", "username": "alice", "password": "..." }
→ 201 { "user": User }        # and/or Set-Cookie

POST /api/auth/login
{ "email": "a@example.com", "password": "..." }
→ 200 { "user": User } + Set-Cookie

POST /api/auth/logout
→ 204

GET /api/auth/me
→ 200 { "user": User } | 401 ErrorEnvelope
```

### 6.2 `User` shape A will type

```ts
type User = {
  id: string
  email: string
  username: string
  bio: string
  avatarUrl: string | null
  platformRole: "USER" | "MODERATOR" | "ADMIN"
  createdAt: string // ISO 8601
}
```

### 6.3 Error shape

```json
{ "error": { "code": "INVALID_PAYLOAD", "message": "...", "requestId": "req_..." } }
```

## 7. Mock strategy (so A never waits for B)

- `VITE_USE_MOCKS=true` keeps `lib/api.ts`'s public API identical.
- Mocks live in `src/lib/mock/`, are in-memory and deterministic, and simulate:
  register, login, logout, `me`, one 401, one 409, and 300 ms latency.
- Mock users: `alice@example.com` / `Password123!`,
  `bob@example.com` / `Password123!`.
- Mock state may persist in `sessionStorage` for reload tests; never in
  `localStorage` (avoid leaking a fake session into real mode).
- Delete or quarantine mocks before the final delivery if they are not needed;
  they must never be reachable when `VITE_USE_MOCKS=false`.
