## 2. Decisions to lock on Day 1

| Decision | Choice | Reason |
|---|---|---|
| Runtime | Node 22 | Matches CI and Vite tooling |
| Framework | React 19 + TypeScript strict | Agreed in README after PR #15 |
| Build | Vite 5.4 | Stable and Node 22 compatible |
| Routing | React Router 7 | Agreed stack direction; file/route config in `router/` |
| Client state | Zustand 5 | Small auth/UI stores without provider nesting |
| Server state | TanStack Query 5 | Cache, retries and invalidation for feeds and profiles |
| Styling | Tailwind CSS 3.4 + CSS variables | Predictable token demos |
| Tests | Vitest 2 + Testing Library | Same Vite pipeline |
| Lint | ESLint 9 + `react-hooks` + `react-refresh` | Current React tooling |
| API base | `import.meta.env.VITE_API_URL`, default `/api` | Same-origin in dev |
| Dev transport | Vite proxy `/api` and `/ws` → `127.0.0.1:8000` | Avoids CORS and cross-site cookies |
| Auth transport | HTTP-only session cookie, `credentials: "include"` | `docs/product-v1.md` D10 |
| Backend offline mode | `VITE_USE_MOCKS=true` | Unblocks A while auth routes are built |
| Naming | Components `PascalCase.tsx`, pages `*Page.tsx`, hooks `use*`, stores `use*Store` | Consistent React conventions |
| API casing | Backend `snake_case` DTO → frontend `camelCase` model | Keeps TypeScript ergonomic; mapping lives in `lib/api.ts` |

**Backend validation is the source of truth.** The client mirrors it for UX only:

- password: 15–128 characters
- username: 3–50 characters, `^[A-Za-z0-9_]+$`
- email: valid, normalised to lowercase
